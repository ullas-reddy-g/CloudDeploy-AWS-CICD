Architecture & Engineering Specification

Overview of the containerization stack, automated CI/CD pipeline, and AWS cloud topology.

Backend & WSGI
  • Python 3.11+: Robust runtime environment.
  • Flask 3.0+: Lightweight, modular web framework.
  • Gunicorn 22.0: Production-grade WSGI server running multiple worker processes with asynchronous timeouts.
  • Pytest: Automated unit, integration, and HTTP endpoint test suite.
Container & Proxy
  • Docker: Multi-layer containerization with non-root security execution.
  • Docker Compose: Multi-container orchestration linking the application container with the reverse proxy.
  • Nginx: Edge reverse proxy handling client requests, security headers, buffering, and SSL termination.
AWS Cloud & CI/CD
  • GitHub Actions: Automated CI test execution and OIDC authenticated CD deployment.
  • Amazon ECR: Secure container image registry storing immutable deployment tags.
  • AWS EC2: Ubuntu host running Docker engine and IAM instance profile.
  • AWS CloudWatch: Consolidated system metrics, alarms, and container log streaming.
Cloud Security & Least-Privilege Architecture
Zero Long-Lived Credentials

GitHub Actions connects to AWS using OpenID Connect (OIDC) identity federation, requesting short-lived STS tokens bound specifically to the GitHub repository and branch name. No AWS access keys are stored in GitHub Secrets.

Non-Root Docker Execution

The Docker container creates a dedicated unprivileged user (clouddeploy UID 10001) preventing privilege escalation vulnerabilities in container runtimes.

IAM Instance Profiles

The EC2 deployment instance uses an attached IAM role with strictly scoped read-only ECR permissions (`ecr:GetAuthorizationToken`, `ecr:BatchGetImage`, `ecr:GetDownloadUrlForLayer`) avoiding hardcoded API credentials on the server.

Automated Rollback Safeguard

Deployment scripts perform health probe validation on GET /health before retiring previous instances, automatically reverting to the last verified image if a failure occurs.
