Architecture & Engineering Specification

Overview of the containerization stack, automated CI/CD pipeline, Render production hosting, and optional AWS cloud topology.

Backend & WSGI
  • Python 3.11+: Robust runtime environment.
  • Flask 3.0+: Lightweight, modular web framework with application factory pattern.
  • Gunicorn 22.0: Production-grade WSGI server running multiple worker processes with asynchronous timeouts.
  • Pytest & Flake8: Automated unit, integration, and PEP8 style enforcement.
Container & Proxy
  • Docker: Multi-layer containerization with unprivileged non-root user (UID 10001).
  • Docker Compose: Multi-container orchestration linking the application container with the reverse proxy.
  • Nginx: Edge reverse proxy handling client requests, security headers, buffering, and SSL termination.
Cloud Hosting & CI/CD
  • GitHub Actions CI: Automated linting, test suite execution with 100% statement coverage, and Docker build/runtime verification.
  • Render Cloud (Live Host): Automated deployment pipeline hosting the containerized application on Render Free Tier.
  • AWS (Optional Extension): Production-ready IAM OIDC trust policies, ECR provisioning scripts, EC2 user-data bootstrap, and CloudWatch agent configurations.
Cloud Security & Least-Privilege Architecture
Zero Long-Lived Credentials

The repository and CI/CD workflows store zero hardcoded secrets. All external deployments rely on automated Git-push synchronization or secured deploy hooks, and optional AWS configurations leverage OpenID Connect (OIDC) identity federation with STS tokens.

Non-Root Docker Execution

The Docker container creates a dedicated unprivileged user (clouddeploy UID 10001) preventing privilege escalation vulnerabilities in container runtimes.

Log Sanitization & Privacy

The in-memory logging buffer filters and redacts any potential sensitive tokens or environment secrets before exposing entries via /api/logs.

Automated Rollback & Health Verification

All deployment workflows and host scripts perform health probe validation on GET /health before declaring a rollout successful, alerting on failures and enabling rapid rollback.
